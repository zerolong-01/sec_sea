# MVP 통합 실행 파이프라인 계획

## 목표와 현재 문제

백엔드·Streamlit UI·데이터가 dev에 병합됐지만 서버별 실행과 데이터 버전 수동 입력이 필요하다. UI 기본 코퍼스 버전은 실제 데이터와 다르고, 병합된 코퍼스 마지막 줄의 JSON 뒤 문자열 때문에 파싱도 실패한다. 루트에서 환경 준비, 데이터 검증, 서버·UI 실행, HTTP 통합 검증을 수행하는 공통 진입점을 제공한다.

- 관련 작업: #7, #8, #9, #16
- 기준 dev: `1c547af`
- 개발 브랜치: `feat/mvp-integration-pipeline`
- 실행 계획 이슈: https://github.com/zerolong-01/sec_sea/issues/17

## 구현 순서

1. 데이터 보완 및 버전 고정
   - b006을 공격 지시·canary 없는 정상 교육 일정 문서로 분리한다.
   - a006/doc006에 합성 canary와 정확한 출력 성공·실패·재검토 기준을 추가한다.
   - h001/h002/h003을 공격 지시를 설명·인용하는 정상 보안 문서로 연결한다. h007과 함께 최소 3건을 확보한다.
   - JSONL 오류를 수정하고 모든 case/document의 source_version을 새 버전으로 올린다.
   - 대표 ID, 기대 검색 순위, 데이터·코퍼스 버전을 별도 manifest에 고정한다.
   - 데이터 가이드와 수동 판정·합의 절차를 갱신한다.
2. 루트 실행 파이프라인
   - `python -m scripts.mvp setup`: 저장소 전용 가상환경·통합 의존성 설치.
   - `python -m scripts.mvp check`: 전체 JSONL/계약 스키마, 참조, 버전, 대표 라벨·검색 기대값 검증.
   - `python -m scripts.mvp serve`: 사전 검증 후 FastAPI·Streamlit 실행, 준비 상태 확인, 종료·실패 시 자식 프로세스 정리.
   - `python -m scripts.mvp verify`: 실제 로컬 HTTP API에서 대표 3건 실행·저장 trace 재조회, 버전·순위·마스킹·manifest 일관성 검증. 외부 모델 키 없이 demo 제공자로 수행.
   - 포트 충돌·잘못된 데이터·서버 시작 실패는 명확한 오류와 비정상 종료 코드로 알린다.
3. UI 연동
   - 같은 데이터 경로와 manifest를 읽고 대표 케이스·정확한 버전을 기본 선택한다.
   - UI 실행 버튼의 API 요청과 trace 렌더링을 검증한다.
4. 회귀 방지와 인계
   - 실제 커밋 데이터, 잘못된 JSONL·버전·문서 매핑·검색 기대값을 검증한다.
   - API 기동→POST 실행→GET 재조회 및 UI를 확인하는 CI를 구성한다.
   - 루트 README에 설치·실행·검증 명령, 주소, 설정과 종료 방법을 기록한다.
