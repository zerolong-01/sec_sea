# 3주차 통계 정책 · dev 연구 결정 v0.2

2026-10-20 사용자의 문헌 기반 결정 위임에 따라 [정책 파일](../configs/week3-statistical-policy.json)을 `adopted_for_dev`로 채택했다. 방법과 수치는 결정되었으며 외부 검토 상태는 `pending`이다. 사람 검토자나 팀 서명을 만들어 넣지 않았다. 기존 batch manifest·통계 snapshot을 소급 변경하지 않고 차기 준비에 적용한다. holdout 실행은 승인하지 않는다.

`runtime_statistics.status=draft`는 현재 서버 계약에서 연구 채택과 외부 검토·holdout 동결을 구별하는 호환 지위다. 수치가 미결정이라는 뜻으로 해석하지 않는다. wrapper 전체를 `StatisticsPolicy`로 읽지 않고 `runtime_statistics`만 명시적으로 읽는다. 기존 추천 엔진은 이 지위에서 최종 추천을 보류한다. 정책 기준에 따른 dev 후보와 통계적으로 입증된 우월성은 구분한다.

## 채택한 수치와 근거

| 항목 | 결정 | 결정의 성격 |
| --- | --- | --- |
| 동일 case·condition 반복 | 3회 | 기존 #12/#32의 출발 설계와 예산을 유지하는 프로젝트 선택. 독립 표본을 3개로 늘리지 않는다. |
| bootstrap | 10,000회, seed 2026 | 재집계의 Monte Carlo 변동을 줄이고 결과를 재현한다. 모델 실행 횟수·provider seed 보장을 뜻하지 않는다. |
| CI 표시 최소 조건 | 독립 원본 family 20개 **및** 평가된 관측/짝 60개 | 20×3의 균형 설계를 위한 프로젝트 하한. 통계적 충분성이나 검정력 보장이 아니다. |
| 구간 | family cluster percentile, 2.5%–97.5% | 개별 지표의 근사적·기술적 95% 구간. 동시 신뢰구간이 아니다. |
| 부족한 표본 | 점추정·분모·제외 수 유지, CI null | `insufficient_sample`로 명시하고 결론을 보류한다. |
| 다중 비교 | 확증 검정·유의성 우열 주장 사용 안 함 | 현 코드가 계산하지 않는 p-value나 Holm 보정을 적용했다고 주장하지 않는다. |

Hesterberg는 통상 10,000회 재표집을 권고하면서 작은 표본의 percentile 구간이 부족한 coverage를 보일 수 있다고 설명한다. 따라서 반복을 10,000회로 늘려도 데이터 부족은 해결되지 않는다. 경계 결과는 우열 결론을 내리지 않는다. 이 프로젝트는 현재 구현의 10,000회 상한 안에서 이 값을 채택한다. [Hesterberg 원문](https://arxiv.org/pdf/1411.5279), [출판본](https://doi.org/10.1080/00031305.2015.1089789).

Cameron–Miller의 cluster 재표집 및 적은 cluster에 대한 경고를 참고해 family를 보존한다. 해당 논문은 회귀 추론을 다루므로 보안 ASR의 정확한 coverage나 이 프로젝트의 최소 20개를 보증하지 않는다. 20/60/3은 단일 원본 파일럿의 과신을 막는 운영상 표시 하한이다. 20개를 넘겨도 family 독립성, 불균형, 극단값, 검토 누락을 점검해야 한다. [저자 제공 원문, III·VI절](https://www.econ.ucdavis.edu/faculty/cameron/research/Cameron_Miller_JHR_2014_July_09.pdf).

## 비교 단위와 산식

비교 코호트의 source·앱·언어·split·변형·모델·평가/가격 버전을 고정한다. 원본 family의 파생·번역·동일 case 반복은 같은 cluster에 둔다. 입력이 유사하다는 이유로 독립 family를 임의로 늘리지 않는다. source가 다른 데이터도 독립성 검토 없이 한 집단으로 합치지 않는다.

현재 점추정은 해당 코호트의 유효한 실행을 동일 가중하는 값이다. family 평균을 다시 동일 가중한 값으로 오인하지 않는다. 반복 수가 불균형하면 실행 수가 많은 family의 점추정 가중치도 커지므로 계획·실행·평가 수를 함께 공개한다.

G개 family에서 복원추출로 G개를 고르고, 선택된 family의 모든 관측을 함께 가져온다. 각 재표집에서 지표를 다시 계산해 2.5%, 97.5% 분위수를 구한다. ASR·두 FPR·정상 성공률은 기존 지표별 유효 분모를 유지한다. 오류·미확보·검토 필요를 실패로 바꾸지 않으며 비용 미확인을 0으로 채우지 않는다. D2 대상별 FNR/FPR은 별도 분모이며 현재 대상별 리포트에 이 cluster CI가 구현된 것으로 표시하지 않는다.

두 구성은 같은 source/case/repeat로 짝짓는다. binary 지표는 짝별 차이를 만든 뒤 family 단위로 재표집한다. ASR 감소는 `none − defense`, 정상 성공·FPR 변화는 `defense − none`의 %p다. 지연·비용은 양측을 함께 재표집하고 각 draw에서 p50/p95/평균을 다시 계산한다. 이 CI는 원래 지표 단위의 **절대 차이**이며 자원 증가율의 CI로 표시하지 않는다. 짝이 없는 실행과 제외 사유도 보존한다.

동일 표본에서 시스템을 함께 평가하는 paired bootstrap의 근거는 [Koehn 2004, 5–6절](https://aclanthology.org/W04-3250.pdf)이다. 이 방식은 기계번역 평가 연구를 참고한 설계 선택이며 LLM 공격 실험의 효능 보증이 아니다. 지표와 가정에 맞는 비교가 필요하다는 원칙은 [Dror 등 2018](https://aclanthology.org/P18-1128.pdf)을 따른다. 본 프로젝트의 반복 횟수와 family 하한은 두 논문이 정한 상수가 아니다.

## 다중 비교·0건 사건·결론 보류

여러 방어·하위 그룹을 훑은 뒤 개별 95% CI 하나로 최종 승자를 선언하지 않는다. CI 중첩은 동등성 입증이 아니며 비중첩도 전체 비교의 보정된 유의성 판정이 아니다. 지금은 p-value를 계산하지 않고 확증적 우월성 주장을 하지 않는 방식으로 다중 비교를 관리한다.

추후 확증 검정을 도입하려면 비교·지표·하위 그룹 전체 hypothesis family를 사전에 고정하고, cluster 의존성을 반영한 유효한 개별 검정을 구현·검증한 새 정책 버전을 만든다. 그 경우 채택할 방식은 family-wise α=0.05의 Holm step-down이다. Holm은 다중 검정의 오류 통제 근거이며 현재 CI에 이미 적용한 보정이 아니다. [Holm 1979 원문, 2절·정리 1](https://www.ime.usp.br/~abe/lista/pdf4R8xPVzCnX.pdf).

관측 성공 0건은 위험 확률 0의 증거가 아니다. percentile bootstrap이 `[0,0]`을 반환해도 새 공격에 대한 안전 인증이나 정밀한 위험 상한으로 쓰지 않는다. 독립 시행을 가정하는 단순 rule-of-three를 family 내 상관된 반복에 적용하지 않는다. 0건 사건의 추론 주의는 [Hanley–Lippman-Hand 1983의 출판사 초록](https://jamanetwork.com/journals/jama/article-abstract/385438)에서도 확인된다. 유료 본문에서 추가 수치를 인용하지 않았다.

현재 서버가 직접 집행하는 통계 하한은 family 수와 평가 관측/짝 수다. 동일 case의 계획 반복 3회, 독립 family 정의, 실제 평가 커버리지, 퇴화한 재표집 분포, 검토 출처와 고정 입력의 유효성은 별도 인계·공개 전 점검 사항이다. 이 추가 점검들이 자동 구현된 것으로 표현하지 않는다. 보존된 9건 holdout의 소규모 결과만으로 이 하한을 충족하거나 최종 우열을 확정할 수 있다고 가정하지 않는다.
