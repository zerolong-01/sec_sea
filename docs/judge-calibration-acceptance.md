# 공개 사람 기준 세트 자동화·실제 judge 검산 기록

2026-11-09, macOS arm64 / Python 3.11.18에서 수행했다.
구현·연구 근거·명령은 [자동화 가이드](judge-calibration.md), 기계 판독 결과는
[실제 외부 기준 보고서](examples/judge-calibration/live-report.v0.1.json)와
[검증 index](examples/judge-calibration/verification.v0.1.json)에 보존한다.

## 구현한 자동화

- 원본 commit·Git blob hash·MIT 라이선스가 고정된 LLMBar 419쌍의 사람 gold 재사용.
- 동일 지시문이 겹치지 않는 개발 20쌍/검산 80쌍의 사전 선정과 응답별 기준 라벨 160개 동결.
- 서비스와 같은 judge 모델·프롬프트·rubric·스키마 검사·판정 함수를 사용한 실제 검산.
- gold를 프롬프트에서 제외하고, 일치율·오판·보류·혼동행렬·신뢰구간·비용을 JSON/CSV로 생성.
- 호출 전 영속 예약, 완료한 응답 재사용, 중단된 유료 호출의 자동 재시도 금지와 오류 연속 시 중단.
- PR의 무과금 CI와, 명시적으로 실행하는 실제 모델 workflow 및 기준 미달 시 종료 코드 2.

연구진이 검수한 공개 gold를 재사용했다. 이 프로젝트의 사람이 새 답변을 검토했다고 표시하지 않는다.
원래 쌍의 지시 이행 gold를 응답별 성공/실패로 대응한 프로토콜이며, 한국어 RAG/이메일의 모든
보안·정상 업무를 사람 기준으로 인증한 결과가 아니다.

## 실제 최종 실행

로컬의 기존 모델 설정을 `--use-generation-config`로 명시적으로 사용했다. `.env`는 변경하지 않았다.
모델은 `gpt-4.1-mini-2025-04-14`, 프롬프트는 `normal-task-judge-prompt-v0.4`, 출력은 strict JSON schema다.
모든 의미 판정 정책과 source gold, 선정 seed, 외부 gate는 실행 전 동결한 값을 유지했다.

| 항목 | 관측 결과 |
| --- | --- |
| 검산 범위 | 균형 선정 80쌍 / 160응답 / 동일 지시문 그룹 80개 |
| 전체 외부 기준 일치 | **52/160 = 32.5%** |
| 지시문 그룹 bootstrap 95% 구간 | 25.625% ~ 39.375% |
| 확정 판정만의 일치 | 52/76 = 68.42% |
| 검토 회송 | 83/160 = 51.875% |
| 미평가/형식 오류 | 1/160 |
| 잘못된 성공 | 9/80 = 11.25% |
| 두 응답을 모두 맞힌 엄격 쌍 일치 | 10% |
| 실제 호출·토큰 | 160회, 입력 244,058 / 출력 60,044 |
| 완료 실험의 추정 비용 | 0.1936936 USD |
| 완료 실험 시간 | 약 534초 |
| 저장 결과 재계산 모델 호출 | 0회 |

**외부 기준 gate는 실패했다.** 목표 94%와 잘못된 성공률 상한 5%에 미달했고, 미평가도 1건 있다.
`python -m scripts.judge_calibration check --output runs/judge-calibration-live-v4-20261109`의
종료 코드 2를 확인했다. 보류/미평가를 분모에서 빼거나, 임계값을 낮춰 통과로 바꾸지 않았다.
현재 모델·rubric 조합의 외부 기준 미달을 자동으로 드러내는 것이 이 결과의 의미다.

| 원본 subset | 응답 수 | 전체 일치율 | 잘못된 성공률 |
| --- | --- | --- | --- |
| Natural | 32 | 56.25% | 0% |
| Neighbor | 32 | 28.125% | 18.75% |
| GPTInst | 32 | 37.5% | 6.25% |
| GPTOut | 32 | 21.875% | 31.25% |
| Manual | 32 | 18.75% | 0% |

이 정확도는 균형 선정 표본과 응답별 대응 프로토콜의 값이다. 논문의 pairwise 인간 일치율,
원본 419쌍 전체의 비례 추정값, 프로젝트 한국어 보안 업무 정확도와 같은 수치로 취급하지 않는다.

## 실제 실행에서 발견하고 수정한 형식 문제

첫 실행에서는 형식 요구가 없을 때 모델이 필수 `required_format` 항목을 생략했다.
중단 시점의 31호출·30오류 기록을 보존하고 필수 필드를 JSON schema에 명시했다.
후속 v0.3 시도는 중복 키·불필요한 필드 등 3회 연속 형식 실패에서 자동 중단했다.
두 시도의 결과를 최종 성능 분모에 섞지 않았다.

최종 v0.4는 제공자에 실제 JSON schema 제약을 전달하고 rubric별 정확한 키를 강제한다.
필수 필드·중복 키를 느슨하게 허용하지 않았으며, 의미 판정 모순/근거 부족은 그대로 보류했다.
모델의 정답 일치 여부를 보고 gold·표본·정확도 기준·보류 정책을 수정하지 않았다.

세 시도의 총 호출은 197회다. 관측 사용량 기반 추정 비용 합계는 약 0.240675 USD,
중단 호출의 남은 예약까지 포함한 금액은 약 0.255395 USD다. 마지막 실행의 상한은 0.9 USD로
낮췄고, 이전 예약과 합쳐도 최초 안내한 추정 1 USD 한도 안에 유지했다.
이는 고정 가격표 계산으로 실제 청구서 금액과 구분한다.

## 소프트웨어 검증과 남은 품질 판단

- 파이프라인 전체 **310개**, 백엔드 전체 **183개**, 총 **493개** 회귀 통과.
- 새 보정 테스트 9개: 공개 label 변조, 개발/검산 분리, gold 유출 방지, 미평가/보류 분모,
  비용 한도 축소, 코드/모델 변경 거부, 중단 예약, 재개 중복 호출을 검증.
- 잘못된 fixture judge가 모든 응답을 성공 처리하면 정확도 50%·잘못된 성공률 100%로 탈락함을 검증.
- 기본 strict JSON schema를 적용한 뒤 네 모드 UI·재전송·수동 수정·CSV 연결 회귀 통과.
- 실제 결과 반복 재생의 동일 report hash와 원본 ledger 불변, 추가 모델 호출 0 확인.

CI의 자동화 검증 통과와 실제 judge의 정확도 gate 실패는 별개다.
동결 검산 세트를 반복 튜닝에 사용하지 말고, 다음 개선은 개발 세트와 별도 도메인 기준으로 진행한다.
`project_domain_human_validation=pending`, `human_validated=false`, holdout 미실행을 유지한다.

로컬 원본 근거는 `runs/judge-calibration-live-20261109`(중단),
`runs/judge-calibration-live-v3-20261109`(형식 오류 중단),
`runs/judge-calibration-live-v4-20261109`(완료) 및 `runs/judge-calibration-fixture-v4-20261109`다.
검산 workflow는 파일로 준비했으며 원격 실행·secret 등록·저장소 push는 수행하지 않았다.
