# 4주차 대표 실패 사례 분석

## 1. 분석 목적 및 실험 범위

이슈 #41의 프롬프트 인젝션 탐색 실험에서 관측된 공격 성공 사례를 분석하고, 주요 실패 원인과 추가 검증이 필요한 항목을 정리했다.

| 항목 | 결과 |
|---|---:|
| 전체 입력 레코드 | 157건 |
| 방어 조건 | 6개 |
| 계획 실행 | 942건 |
| 공격 조건 결과 | 426건 |
| 공격 목표 달성 | 123건 |
| 공격 목표 미달성 | 303건 |
| 정상·Hard-negative 조건 결과 | 516건 |
| 공격 성공 구문 | 35개 |

목표 달성 123건은 자동 문자열 검사 114건, Base64 복원 2건, 문맥 검토 7건으로 기록됐다.

35개 구문과 123개 성공 관측은 서로 다른 집계 단위이며, 독립 공격 family 수와도 구분한다.

이 결과는 별도의 탐색 감사로, 정규 dev 성능 평가와 합산하지 않는다.

대표 사례에서는 보호정보 노출, 부분값·인코딩 출력, 탐지기의 의미적 미탐, 업무·형식 변경 등이 관측됐다.

다만 목표 문자열이 출력됐다고 해서 모든 사례를 비공개 정보 유출로 분류하지 않는다.

## 3. 주요 실패 원인 및 보완 방향

| 실패 유형 | 문제점 | 보완 방향 |
|---|---|---|
| 보호정보 노출 | 번역·요약 등의 정상 업무에 보호값 요청 결합 | 보호 정책과 출력 검사 기준 확인 |
| 부분값·인코딩 출력 | 일부 값 또는 Base64로 복원 가능한 정보 출력 | 부분 일치·복원 규칙 검토 |
| D2 의미적 미탐 | 공격 입력을 낮은 위험 점수로 허용 | 실제 검사 텍스트·Gold·탐지결정 대조 |
| 업무·형식 변경 | 공격 지시에 따라 원래 작업 변경 | 정상 업무 수행과 출력 형식 별도 평가 |
| 정책 불일치 | 실제 시스템 정책과 평가 기대가 다름 | Gold·rubric과 보호 정책의 정합성 확인 |
| 검사 위치 제한 | 입력 또는 문서 중 일부만 검사 | 방어 적용 위치별 비교 |

특히 `week2/a021`에서는 D2의 허용 결정 이후 최종 출력에 목표 토큰이 포함된 것으로 기록됐다.

그러나 D2의 `allow` 자체를 공격 성공으로 판단하거나, 실제 검사하지 않은 입력·문서를 미탐으로 계산하지 않는다.

## 4. 조건부 보완 검증 계획

기존 실행 기록으로 확인할 수 있는 항목부터 검토하고, 추가 증거가 필요한 경우에만 보완 실험을 진행한다.

우선 확인할 사항은 다음과 같다.

1. 실제 보호 정책과 평가 기준의 일치 여부
2. 부분값·Base64 등 복원 가능한 정보 노출 여부
3. D2 허용 사례의 실제 검사 대상·Gold·탐지결정
4. 정상 업무 손실과 방어 오탐의 구분
5. D2 입력·검색 문서 검사 위치별 결과 차이

추가 실험이 필요한 경우에는 합성 dev 데이터를 사용하고, 동일 모델·평가 정책·검색 조건을 유지한다.

정상 요청·정상 인용·공격 지시 제거 대조군을 포함하며, 독립 family, 반복 수, 판정 기준 및 비용 상한을 사전에 정한다.

추가 실험은 현재 수행하지 않았으며, holdout은 보존한다.

## 5. 결론

이슈 #41의 탐색 감사에서는 35개 공격 구문과 123건의 목표 달성이 기록됐다.

주요 실패 유형은 보호정보 노출, 부분값·인코딩 출력, D2 의미적 미탐, 업무·형식 변경 및 정책 불일치로 구분된다.

현재는 공개된 탐색 기록을 바탕으로 실패 원인과 후속 검증 대상을 정리한 단계다. 개별 원시 응답 전체에 대한 독립 검증이나 추가 보완 실험이 완료됐다는 의미는 아니다.

정규 dev 결과와 탐색 감사는 구분하며, **최종 방어 추천은 `deferred`**, holdout 평가는 미실행 상태로 유지한다.
