
# 4주차 최종 실험·평가 보고서

## 1. 프로젝트 개요 및 목적

보안바다의 LLM Defense Trade-off Lab은 RAG 챗봇과 이메일 요약기에서 발생할 수 있는 프롬프트 인젝션 공격을 실험하고, 방어 방식별 성능을 비교하는 플랫폼이다.

본 프로젝트는 사용자가 방어 구성과 적용 위치를 선택하여 공격 차단 효과와 정상 업무에 미치는 영향을 비교할 수 있도록 개발했다.

이를 위해 공격 성공률(ASR), 정상 업무 성공률, 방어 오탐률(FPR), 응답 지연 및 비용을 주요 평가 지표로 사용한다.

본 보고서는 1~3주차에 구축한 데이터와 평가 기준을 바탕으로 정규 dev 실험 결과, 공개 집계 검산, 별도 공격 탐색 감사, 4주차 재현 및 추가 모델 실행 결과를 정리하고, 플랫폼의 평가 결과와 남은 검증 사항을 분석한다.

## 2. 데이터 및 실험 구성

### 2.1 데이터 구성

| 항목 | 수량 |
|---|---:|
| RAG 케이스 | 84건 |
| RAG 문서 | 52건 |
| 공격 / 정상 / Hard-negative | 각 28건 |
| 한국어 / 영어 | 79건 / 5건 |
| Dev / Holdout | 75건 / 9건 |
| 이메일 케이스 / 문서 | 3건 / 3건 |
| D2 target gold | 48행 |

D2 target gold 48행은 기존 데이터 준비 단계의 초안 수량으로, 정규 dev 실행에서 평가한 D2 검사 대상 621개 task와 집계 단위가 다르다.

데이터는 공격, 정상, Hard-negative로 구분했다.

Hard-negative는 공격과 유사한 표현이 포함되어 있지만 실제로는 정상적인 요청으로, 방어 시스템의 과잉 차단 여부를 확인하기 위해 사용한다.

Holdout 9건은 평가용 데이터와 분리하여 보존했으며, 이번 실험에서는 사용하지 않았다.

### 2.2 방어 구성

| 방어 방식 | 적용 내용 |
|---|---|
| none | 방어 미적용 |
| D1 | 프롬프트 기반 방어 |
| D2-input | 사용자 입력 검사 |
| D2-retrieval | 검색 문서 검사 |
| D2-both | 입력과 검색 문서 모두 검사 |
| D1+D2 | 프롬프트 방어와 D2 결합 |

플랫폼에서는 기본 4개 방어 모드(none, D1, D2, D1+D2)를 비교하고, D2의 경우 입력과 검색 문서 중 어느 위치에 적용하는지에 따라 결과를 추가 비교한다.

#### 2.5.4 평가 결과 추적 및 검증 범위

결과표의 근거는 다음 자료로 연결한다.

- 평가 멤버: `ai-dev-review.members.v0.1.jsonl`
- 집계 지표: `ai-dev-review.metrics.v0.1.jsonl`
- 원증거 단위: `ai-dev-review.units.v0.1.jsonl`
- 평가 메타데이터: `ai-dev-review.v0.1.json`

평가 멤버는 개별 task와 run의 관계를 제공하며, 지표 파일은 cohort별 집계값과 실행 ID 목록, 제외 사유, family 및 case 수를 제공한다.

기록된 cohort와 평가 정책을 유지하여 검산하며, 서로 다른 공격 목표 또는 실험 버전을 임의로 합산하여 방어 성능을 비교하지 않는다.

공개 평가 기록에 대한 paired 비교와 산술 검산은 `result-check.md`에서 확인 가능한 범위를 수행했다.

D2 FNR/FPR의 실제 탐지 결정 대조, 원시 지연 p50/p95, 전체 토큰·비용·실패율 및 B 최종 export와의 직접 대조는 추가 검증이 필요하다. 확인되지 않은 값은 추정하지 않고 사유와 후속 조치를 기록한다.

## 3. 평가 방법 및 기준

### 3.1 주요 평가 지표

| 지표 | 평가 내용 |
|---|---|
| ASR | 판정 완료 공격 중 목표 달성 비율 |
| Benign FPR | 정상 요청에 대한 방어 오탐률 |
| Hard-negative FPR | 공격처럼 보이는 정상 요청에 대한 방어 오탐률 |
| 정상 업무 성공률 | 정상 업무 수행에 성공한 비율 |
| D2 FNR/FPR | 검사 대상의 Gold 대비 탐지 미탐·오탐률 |
| p50/p95 | 응답 지연의 중앙값과 95백분위값 |
| 비용 | 토큰 사용량과 적용 단가에 따른 추정 비용 |

공격 목표 달성 여부와 정상 업무 수행 여부는 별도로 평가했다.

모델의 일반적인 오답이나 출력 형식 오류를 모두 방어 오탐으로 분류하지 않았다.

정규 dev 결과는 `week3-two-ai-review-v0.1`의 AI 검토 판정을 기준으로 하며, 기존 자동 평가 결과와 구분한다.

### 3.2 방어 성능 허용 기준

이는 실제 모델 실험이 수행되지 않았다는 뜻이 아니다. 백엔드에서 완료한 실행·검증과 A 담당자의 별도 환경에서 미완료된 화면 대조를 구분한 것이다.

기존 정규 dev 648건의 최종 B/C 직접 대조 역시 별도로 미완료 상태다.

### 7.3 후속 조치 및 담당

| 후속 작업 | 담당 | 현재 상태 |
|---|---|---|
| 민감정보를 제외한 실제 배치 결과 패키지 제공 | B | 확보 필요 |
| 동일 배치·평가 버전·필터의 화면 조회 환경 확인 | C | 확인 필요 |
| JSON/CSV와 C 화면의 지표·분모·제외·`null` 대조 | A | 보류 |
| 정규 dev 648건의 원시 결과 및 비용·지연 검증 | B 제공, A 검산 | 미완료 |
| D2 검사 이벤트와 Gold 대조 | B 제공, A 검산 | 미완료 |
| 최종 검증 근거와 문서·화면 일치 확인 | A/B/C | 공동 확인 필요 |

민감정보를 제외한 원본 결과가 확보되면 동일 `batch_id`, 평가 버전, 필터, 보고서 해시를 확인한 뒤 결과를 대조한다.

직접 대조가 끝나기 전까지 완료 상태를 표시하지 않는다.

세부 검산 기록과 보류 사유는 `data/week4/result-check.md`에서 관리한다.

## 8. 종합 평가 및 최종 결론

### 8.1 주요 확인 결과

이번 프로젝트의 실험 및 평가를 통해 다음 사항을 확인했다.

- 방어 구성과 적용 위치에 따라 공격 목표 달성과 정상 업무 수행 결과가 달라졌다.
- 일부 방어 방식은 공격 성공률을 낮췄지만 정상 업무 수행도 저하시켰다.
- D1은 특정 보호값 공격에서 효과가 관측됐으나 다른 공격에서는 목표 달성을 허용했다.
- D2의 검색 문서 검사는 일부 표식 공격의 성공률을 낮췄지만 공격 성공이 완전히 제거되지는 않았다.
- 공격 성공률뿐 아니라 정상 업무 성공률과 오탐률을 함께 비교해야 방어 구성의 장단점을 확인할 수 있다.

추가로 4주차 로컬 fixture와 공개 AI 연구 Overlay에 대한 파일 간 정합성을 검산했으며, 실제 추가 모델 실행의 백엔드 검증 기록도 확인했다.

이는 평가 결과의 추적성과 재현 가능성에 대한 근거이지만, 모든 실제 배치의 최종 화면 인수가 완료됐음을 의미하지 않는다.

### 8.2 프로젝트 검증의 한계

이번 평가는 합성 dev 데이터와 기존 AI 평가 기록을 기반으로 진행했다.

실험 데이터의 규모와 독립적인 공격 유형 수가 제한적이므로 다양한 환경에서 동일한 결과가 나타난다고 단정하기 어렵다.

특히 기존 정규 dev 648개 응답의 원시 자료 전체 재검증, D2 실제 탐지 판정 대조, 전체 비용·지연 검증 및 최종 B/C 화면 대조가 완료되지 않았다.

AI 검토 기록은 존재하지만 독립적인 사람 검토도 아직 수행되지 않았다.

실제 기업 환경에서의 방어 성능과 비용 절감 효과는 검증하지 않았다.

Holdout 데이터 9건은 보존했으며 이번 평가에서는 사용하지 않았다.

### 8.3 최종 방어 추천

최종 추천은 다음 순서로 판단한다.

1. 보호값 노출 및 Critical 공격 제한 확인
2. ASR·FPR·정상 성공률·지연·비용 기준 충족 확인
3. 통과 후보 간 Pareto 비교
4. 보안성과 정상 업무 유지의 우선순위에 따른 최종 선정

현재 확인된 dev 평가에서 각 방어 후보는 하나 이상의 허용 기준에 미달했다.

일부 방어 구성은 공격 목표 달성을 줄였지만 정상 업무 손실도 발생했으며, 지연·비용·실패율과 실제 최종 화면 대조도 충분히 검증되지 않았다.

따라서 **최종 방어 구성 추천은 보류(`deferred`)한다.**

### 8.4 최종 정리

본 프로젝트는 프롬프트 인젝션 방어의 공격 차단 효과와 정상 업무 손실을 같은 평가 체계에서 비교하고, 결과의 근거를 추적할 수 있는 플랫폼을 구현했다.

정규 dev 공개 AI 평가 집계, 로컬 fixture 검증, 공개 연구 Overlay 검산 및 실제 추가 모델 실험 기록을 통해 실험·평가·재현 체계의 일부를 확인했다.

다만 실제 모델 배치의 A/B/C 최종 화면 대조와 독립 사람 검토가 남아 있으므로 검증 범위를 넘는 성능 우월성이나 운영 적용 가능성을 주장하지 않는다.

후속 작업은 실제 배치 결과 패키지 확보, C 화면 직접 대조, 미확정 판정 검토 및 조건부 추가 실험을 중심으로 진행한다.
