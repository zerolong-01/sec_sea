# [추가 연구] 성능 평가 기준 선정 근거 및 반복 실험 검토

## 1. 연구 목적 및 기준 선정 근거

본 프로젝트에서는 AgentDojo, InjecAgent, Microsoft PyRIT, NIST GAI Profile 등의 연구·기관 자료를 참고하여 공격 방어 성능과 정상 업무 수행 능력을 함께 평가하도록 설계하였다.

GitHub 이슈 #12에서 평가 기준의 선정 절차를 수립하고, 이슈 #43에서 다음 네 가지 개발 목표를 채택하였다.

| 평가 지표 | 선정 기준 및 이유 |
|---|---|
| ASR ≤5% | 공격 성공률을 5% 이하로 제한하여 공격의 95% 이상을 방어하는 것을 목표로 설정 |
| Benign FPR ≤5% | 일반 정상 요청의 과잉 차단을 20건 중 1건 이하로 제한 |
| Hard-negative FPR ≤10% | 공격과 혼동하기 쉬운 정상 요청의 과잉 차단을 10건 중 1건 이하로 제한 |
| 정상 업무 성공률 ≥90% | 정상 업무 10건 중 최소 9건을 성공적으로 수행하는 것을 목표로 설정 |

해당 수치들은 외부 연구에서 직접 제시한 표준값이 아니라, 참고 문헌의 평가 원칙과 프로젝트의 개발 목적을 고려하여 자체 선정한 탐색적 목표이다.

## 2. 추가 실험 방법

작성자는 기존 개발용 데이터 60종을 대상으로 GPT-4.1 mini 모델을 이용한 실제 OpenAI API 실험 720건을 수행하였다. 작성자는 `runs`에 저장된 실행 결과 720건을 하나씩 직접 확인하고, 자동 판정에서 잘못된 부분을 수정한 뒤 공격 성공률과 정상 업무 성공률을 계산·집계하였다. 이후 누락이나 오류 여부를 확인하기 위해 AI 보조 재검토를 추가로 진행하였다.

**평가 순서: API 실행 → 작성자 원본 전수 수동 검산 → 자동 판정 오류 수정 → 집계 → AI 보조 재검토.** AI는 최초 수동 판정을 대신한 것이 아니다.

다만 이 PR에는 개별 수동 판정 결과와 실행 원본을 연결하여 집계 수치를 별도로 재현할 수 있는 검산 근거가 포함되어 있지 않다. 따라서 아래 통계는 작성자의 원본 전수 수동 검산에 기반한 **작성자 보고값**이며, PR에서 독립 재집계가 완료된 최종 성능으로 표시하지 않는다.

- 공격 25종, 일반 정상 25종, Hard-negative 10종
- 방어 방식 4종(none, D1, D2, D1+D2)
- 동일 사례별 3회 반복

`60종 × 4모드 × 3회 = 720건`은 반복 실험 구성이다. 실행 기록에는 최종 응답 외에 차단 등 다른 상태도 포함될 수 있으므로, 720건 모두에서 정상적인 최종 답변이 생성되었다는 뜻은 아니다. 기존 정규 dev 648건·추가 모델 216건의 평가 분모와 합치지 않는다.

실험 원본은 별도 보관되어 있으나 이 PR에는 실행 ID별 수동 판정과 재집계 과정을 연결한 근거가 없다. 향후 독립 재현 자료를 제출할 경우 모델 ID, case ID와 split, D2 검사 위치, 입력·정책·rubric 버전 및 해시, 실행 실패·미확정 처리 기준, 지표별 분자·분모와 집계 방법을 함께 기록해야 한다. 720건의 작성자 수동 검산 완료 여부와 별도의 독립 검산 가능 여부는 구분한다.

## 3. 실험 결과

D1+D2 방어 방식에 대한 작성자의 원본 수동 검산·집계값은 다음과 같다. 공격 성공률은 15/75, 정상 업무 성공률은 90/105로 보고하였다. FPR은 명시적 차단을 기준으로 한 별도 집계다. 독립적인 재집계 근거가 PR에 연결되지 않았으므로 정책 통과 또는 최종 추천이 검증되었다고 단정하지 않는다.

| 평가 지표 | 기존 목표 | 작성자 수동 검산 집계값 (PR 독립 검산 미완료) |
|---|---|---|
| ASR | ≤5% | 20.0% |
| Benign FPR | ≤5% | 차단 기준 4.0% |
| Hard-negative FPR | ≤10% | 차단 기준 0% |
| 정상 업무 성공률 | ≥90% | 85.7% |

작성자의 수동 검산·집계 결과, ASR은 무방어 43/75(57.3%), D1+D2 15/75(20.0%)였다. 이는 작성자 집계 기준 37.3%p 차이다. 실제 공격 유형별 결과와 미확정 판정 처리까지 재현할 자료는 이번 PR에 포함되지 않았으므로, 이를 검증된 최종 방어 성능으로 확정하지 않는다. 채택 정책에 따른 최종 판단은 공격 목표별 평가와 미확정 판정의 분모 처리 기준을 함께 확인해야 한다.

작성자의 수동 검산·집계 기록에서는 Hard-negative 전체 120건에서 명시적인 차단 사례가 없고 일부 응답은 내용이 불충분했다고 보고하였다. 이 120건은 네 모드 전체(`10종 × 4모드 × 3회`)이며, D1+D2 한 모드의 계획 표본은 30건이다. 이번 PR에서는 해당 기록의 실행별 근거가 별도로 연결되어 있지 않다. 차단 기준 FPR은 내용 손실·과도한 변형을 포함하는 프로젝트 FPR과 같다고 간주하지 않으며, 차단되지 않았다는 사실만으로 정상 업무 성공을 뜻하지 않는다.

## 4. 결론 및 향후 계획

### 이번 PR 검토에서 새로 생성한 근거

원격 최신 dev와 화면·Windows 인코딩 수정을 반영한 코드에서 데이터 계약, 전체 회귀, 로컬 HTTP/UI, h007 네 모드의 별도 판정·조회·이력·CSV, 공개 사람 정답을 사용하는 fixture 판정 자동화를 재실행했다. 실제 실행 환경·커밋·명령·로그 해시와 확인 범위는 [재실행 검증 기록](validation-2026-11-10.md)에 연결한다. 이 기능 검증을 위의 실제 모델 성능 수치가 검산되었다는 근거로 사용하지 않는다.

### 추가 실험 수치의 상태

이번 기록은 실제 API 실험 720건에 대한 작성자의 원본 전수 수동 검산, 오류 수정 및 집계와 그 이후의 AI 보조 재검토를 정리한다. 다만 이번 PR에서는 해당 집계를 독립적으로 재현할 근거가 연결되지 않아, 성능 수치를 검증된 최종 결과나 목표 달성으로 확정하지 않는다.

현재 설정된 5%·5%·10%·90%는 개발 단계의 연구 목표로서 유지하되, 해당 수치의 최적성이 검증된 것은 아니다.

후속 과제는 이미 수행한 720건의 수동 검산을 반복하는 것이 아니라, 필요한 경우 보관된 원본과 판정·집계 근거의 연결성을 보완하는 것이다. 기존 별도 judge 검증의 `human_validated=false`는 이 720건의 작성자 전수 수동 검산 여부와 혼동하지 않는다. 최종 방어 구성 추천 `deferred` 및 holdout 미실행 상태는 유지한다.
