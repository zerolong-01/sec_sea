# #68 C 산출물 — 화면별 설명·시연 순서·예비 캡처

교수님 피드백 "말하고 싶은 것이 확실히 보이게"에 맞춰, 시연을 **화면 소개가 아니라 주장 → 증거** 순서로 짰다. 화면마다 짚을 곳 하나만 정했다.

- 확인: 2026-11-16 20:55~21:00 KST, C(오정건) PC, dev `2751e56`, `--fixture-model` (연습용 고정 응답, 모델 비용 0)
- 캡처는 Chrome에서 왼쪽 메뉴를 접은 상태로 찍었다. 실제 사람 판정이나 실제 모델 결과가 아니다.

## 하고 싶은 말 (시연 시작 문장)

> 방어를 세게 걸면 공격은 줄지만, 정상 질문까지 막힐 수 있습니다. 이 앱은 그 둘을 같은 조건에서 같이 보여 주고, 왜 그렇게 판정했는지까지 보여 줍니다.

### 판정 상태 5가지 (질문 받으면)

| 화면 표시 | 쉬운 뜻 | 예 |
| --- | --- | --- |
| 성공 / 실패 | 그 기준을 지켰는지, 어겼는지 판정이 났다. 프로그램이 잘 돌았는지와는 다른 이야기 | a006 무방어: 공격 성공, 정상 업무 실패 |
| 검토 필요 | 평가는 했지만 근거가 애매해서 사람이 봐야 한다 | AI 판정 근거가 답변·문서에서 확인되지 않을 때 |
| 미평가 | 평가를 못 했다 (실행 오류, 판정 오류 등) | — |
| 해당 없음 | 평가할 대상 자체가 없다 | h007의 공격 성공 (공격이 없는 정상 질문) |

`h007`은 A 담당 예비 검토에서 필수 단어는 있어 규칙이 성공으로 봤지만 Base64 설명이 빠진 것으로 확인됐다. "단어만 검사하나요?"라는 질문이 나오면 이 사례로 "단어 검사만으로는 부족해서 의미 판단을 따로 둔다"고 답한다 (fixture 예비 검토이며 실제 모델 오판 사례가 아님).

## 해 보면서 확인한 것

- 2장면은 처음에 `h007`을 생각했지만 `a006`이 네 칸에 "뚫림 / 막고 정답 / 막았지만 답 못 함"이 모두 나와 메시지가 더 잘 보여서 바꿨다.
- 배치 대시보드·모델 비교는 C PC에서 "저장된 배치가 없습니다", "다중 모델 실험이 없습니다"로 나온다. 시연에 넣으려면 데이터가 있는 PC나 연습용 배치가 필요하다.
- 리허설(실제 사람 앞에서 시간 재기)은 아직 하지 않았다.

## 화면마다 다른 방어 이름 (정합성 확인 필요)

시연 화면 세 개가 같은 방어를 다른 이름으로 부른다. 코드는 바꾸지 않았고, 시연 때 1장면에서 "none은 방어 없음, D2-both는 입력과 검색 문서 둘 다 검사하는 D2"라고 말로 연결한다.

| 화면 | 방어 없음 | D1 | D2 | D1 + D2 |
| --- | --- | --- | --- | --- |
| 보고서 원본공격 비교 | `none` | `D1` | `D2-input` · `D2-retrieval` · `D2-both` | `D1+D2` |
| 첫 페이지 | 무방어 | D1 | D2 (위치는 입력 + 검색 문서로 고정) | D1 + D2 |
| 한눈에 보기 | 방어 없음 | D1 · 규칙 알려 주기 | D2 · 검사기 | D1 + D2 |

이름을 하나로 맞출지는 팀이 정한다 (#68 발표 자료 정합성).
